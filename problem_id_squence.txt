Step 1: Reset the TiDB allocator
Keep the ESP8266 stopped. Since your existing records end at ID 84, first run:
USE espdemo2;

SELECT MAX(id) AS last_id FROM logs;


If the result is 84, execute this TiDB-specific command:
ALTER TABLE logs FORCE AUTO_INCREMENT = 85;


TiDB requires FORCE when lowering an existing auto-increment value.

Step 2: Verify the result
Run:
SHOW CREATE TABLE logs;


Then:
SHOW TABLE logs NEXT_ROW_ID;


The second command, if supported by your TiDB version, shows the next auto-increment allocation. Look for AUTO_INCREMENT in the output.
Step 3: Test one insertion
Before restarting the ESP8266, you can test the table directly:
INSERT INTO logs (value1, value2, value3)
VALUES ('test1', 'test2', 'test3');

SELECT * FROM logs ORDER BY id DESC LIMIT 3;


If the new test row receives ID 85, the allocator reset worked. You can then restart your ESP8266.
If the new row receives a large ID again, stop and do not repeat the deletion. TiDB's ID cache may still be responsible.
